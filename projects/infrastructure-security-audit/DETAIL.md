### Web.py | 웹 소스·설정 파일 분석

SSH/SFTP로 지정한 웹 경로의 HTML과 소스 파일을 읽고 파일 종류별 점검 적용. 웹 애플리케이션 소스·서버 설정의 분석을 위해 Apache·Nginx·Tomcat·PHP 표준 설정 경로도 탐색 대상에 포함함.

| 처리 단계 | 내용 |
| --- | --- |
| 파일 수집 | 지정한 원격 웹 경로와 표준 설정 경로에서 분석 대상 수집 |
| 파일 분기 | HTML·소스·설정 파일을 구분하고 해당 점검 적용 |
| 규칙 적용 | EP·IA·PR·IS·CC 항목의 코드·설정 패턴 분석 |
| 증적 기록 | 파일 경로, 줄 번호, 일치 코드 일부, 상세 상태와 수집 오류 기록 |
| 결과 출력 | 화면에는 코드별 요약, JSON에는 파일별 상세 결과 저장 |

점검 항목을 오류 노출·인증·비밀번호 복구·세션·로그인 요청 제한의 다섯 항목으로 구분함. 로그인·세션 관련 단어와 실제 처리 코드의 구분을 위해 파일 경로·코드 패턴을 함께 분석함.

| 코드 | 점검 항목 |
| --- | --- |
| EP | 상세 오류·디버그 정보 노출, 오류 페이지 설정 |
| IA | 인증 처리, 클라이언트 측 인증 의존 패턴 |
| PR | 비밀번호 복구 과정의 난수·토큰 처리 |
| IS | 세션 생성·갱신·만료, 예측 가능한 식별자 |
| CC | 로그인 처리, 요청 제한·지연 설정 |

CC는 로그인 처리와 요청 제한·지연 설정을 읽는 정적 점검으로 구성함. 반복 로그인 요청 전송 없음.

#### 원격 파일 수집과 규칙 적용 순서

웹 점검은 원격 서버의 파일을 읽는 단계에서 시작함. 지정한 웹 경로의 소스와 표준 설정 경로를 대상으로 삼고, 읽은 파일의 종류에 맞춰 점검 항목을 적용함. 소스 파일에서 찾을 코드 패턴과 서버 설정에서 찾을 설정값을 같은 조건으로 처리하지 않도록 분기함.

1. **분석 경로 지정** — SSH/SFTP로 읽을 웹 경로를 정함. 애플리케이션 파일과 Apache·Nginx·Tomcat·PHP의 표준 설정 파일을 수집 대상으로 구분함.
2. **파일 유형 확인** — HTML, 애플리케이션 소스, 서버 설정을 구분함. 같은 인증 관련 문자열이라도 파일의 용도와 실제 처리 위치에 따라 해석을 달리함.
3. **항목별 패턴 적용** — 오류 노출, 인증, 비밀번호 복구, 세션, 로그인 요청 제한을 각각 EP·IA·PR·IS·CC로 처리함. 한 파일에서 여러 항목의 패턴이 발견되면 해당 코드의 결과와 연결함.
4. **탐지 위치 보존** — 파일 경로·줄 번호·일치 코드 일부를 증적으로 남김. 화면 요약에서 의심 항목을 찾은 뒤 실제 파일의 해당 위치로 돌아가 원인을 확인할 수 있도록 구성함.
5. **읽기 실패 분리** — 파일에서 의심 패턴을 찾은 경우와 파일 자체를 읽지 못한 경우를 상세 상태와 오류로 구분함. 수집하지 못한 파일을 정상 분석한 파일과 같은 결과로 해석하지 않음.

로그인 페이지로 이동시키는 문자열과 계정 입력을 처리하는 코드를 구분하는 문제가 파일 분기·규칙 수정으로 이어짐. 경로 제외만으로 오탐을 해결하면 실제 인증 처리 파일까지 빠질 수 있어, 파일 경로와 코드의 동작을 함께 검토함.

#### 다섯 항목의 확인 대상

| 항목 | 파일에서 대조한 내용 | 결과 검토에 사용한 구분 |
| --- | --- | --- |
| EP | 오류 처리 코드, 디버그 정보, 오류 페이지 관련 설정 | 상세 오류를 표시하는 코드와 일반적인 오류 처리 문자열 구분 |
| IA | 로그인 입력과 인증 처리, 클라이언트 측 판단 패턴 | 단순 화면 이동과 실제 인증 처리기 구분 |
| PR | 비밀번호 복구에 쓰이는 난수·토큰 처리 | 관련 단어의 등장과 복구 처리 코드의 위치 구분 |
| IS | 세션 생성·갱신·만료와 식별자 처리 | 일반 설정 문자열과 실제 세션 초기화 패턴 구분 |
| CC | 로그인 처리, 요청 제한·지연 설정 | 소스·설정에서 확인한 조건과 실제 요청 차단 결과 구분 |

분석 결과는 코드·설정에서 발견한 점검 후보임. 예를 들어 애플리케이션에서 요청 제한 설정을 찾지 못해도 외부 WAF나 프록시에 제한이 적용돼 있을 수 있음. 해당 파일의 증적을 남기고 동적 동작이나 외부 정책을 확인할 대상으로 구분함.

### Web.py | 요약과 상세 증적 분리

화면 출력은 코드별 요약, JSON은 파일별 판정·증적으로 분리함. 파일 경로·줄 번호로 탐지 위치를 확인하고 일치 코드와 탐지 조건을 대조함. 수집 오류도 상세 결과에 기록하고 비밀번호·토큰 패턴은 마스킹 처리.

화면 요약의 `취약`에는 `점검 필요`와 `오류`도 포함됨. 의심 코드 탐지와 파일 수집 실패가 같은 요약으로 표시될 수 있어 JSON의 상태·증적·오류를 함께 확인함. `양호`는 수집 범위와 해당 없음 항목을 포함한 정적 분석 결과임.

#### 화면 요약에서 파일별 증적으로 이동

화면 요약은 항목 코드별로 전체 결과를 빠르게 확인하는 용도로 사용함. 오탐 원인 분석은 JSON의 파일별 결과를 기준으로 수행함. 두 출력이 같은 정보를 반복하지 않도록 요약에는 코드별 상태, 상세에는 위치·일치 내용·오류를 남김.

| 확인 순서 | 출력에서 확인한 값 | 분석에 사용한 내용 |
| --- | --- | --- |
| 항목 선택 | EP·IA·PR·IS·CC 코드와 화면 상태 | 추가 확인할 항목 선정 |
| 파일 확인 | 상세 결과의 파일 경로와 줄 번호 | 도움말·설정·실제 처리 코드 여부 판단 |
| 패턴 대조 | 일치 코드 일부와 항목 조건 | 단순 문자열과 실제 처리 동작 구분 |
| 오류 확인 | 상세 상태와 수집 오류 | 탐지 결과와 읽기 실패 구분 |
| 출력 보호 | 비밀번호·토큰 패턴 마스킹 | 결과 파일에 인증정보가 그대로 남지 않도록 처리 |

`취약`으로 요약된 항목 안에 수집 오류가 있는 경우에는 코드의 결함 여부보다 수집 실패 원인을 먼저 확인함. 반대로 의심 패턴이 기록된 경우에는 파일·줄 번호를 따라가 실제 처리 코드를 대조함. 웹 오탐 수정에서도 이 순서로 도움말·로그아웃 처리·일반 설정 문자열을 분류함.

### VH.py | 가상화 플랫폼별 설정 수집

HV-01~HV-25의 점검 진입점을 구성하고 ESXi·XenServer의 수집 방식을 분리함. ESXi는 pyVmomi를 통한 HTTPS vSphere API 사용, SSH 연결 차단. XenServer는 SSH로 계정·인증·서버 설정을 조회하도록 구성함.

| 플랫폼 | 수집 방식 | 조회 대상 |
| --- | --- | --- |
| ESXi | HTTPS vSphere API, SSH 연결 차단 | 세션·계정·권한·로그·VM 장치·가상 스위치 설정 |
| XenServer | SSH | 계정·인증·시각 동기화·원격 로그 설정 |

판정은 `양호`, `취약`, `검증필`, `오류`, `해당없음`으로 구분함. 수집한 설정값의 조건 판정, 수집 실패, 외부 자료 대조 필요 항목을 구분해 출력함.

패치 항목 HV-25는 버전·빌드 정보만으로 최신 패치 적용을 확정하기 어려워 `검증필`로 처리함. 벤더 권고·변경 이력은 별도 대조 필요함. ESXi 전용 항목은 XenServer 적용 여부를 별도로 판정함. 두 도구의 동작 범위는 설정 조회·결과 출력이며 대상 설정의 자동 변경 기능은 없음.

#### 플랫폼 선택부터 설정 수집까지

1. **플랫폼별 의존성 확인** — ESXi와 XenServer에 필요한 패키지를 구분하고 접속 정보 입력 전에 누락 여부를 확인함. 필수 모듈이 없으면 설정 수집 이전 단계에서 원인을 확인할 수 있도록 변경함.
2. **수집 경로 선택** — ESXi는 HTTPS vSphere API, XenServer는 SSH로 분리함. ESXi를 선택한 경우 SSH 수집 경로로 진행하지 않도록 처리함.
3. **연결 상태 확인** — 연결이 성립하지 않은 상태와 설정값을 받아 판정한 상태를 구분함. API 미연결 시 오류가 각 항목으로 전달되는 처리를 모의 입력으로 확인함.
4. **설정값과 적용 대상 대조** — 수집값을 항목별 조건과 비교함. 플랫폼이 다르거나 해당 설정의 적용 대상이 아닌 경우에는 `해당없음`을 구분함.
5. **추가 대조 항목 분리** — 버전·빌드만으로 결론을 낼 수 없는 패치 항목은 `검증필`로 남김. 수집된 값과 별도 대조가 필요한 근거를 구분함.

| 상세 상태 | 적용한 의미 | 오류 분석에서의 구분 |
| --- | --- | --- |
| 양호 | 수집한 값이 해당 항목의 기준을 충족함 | 수집 범위 안에서의 판정 |
| 취약 | 수집한 값이 항목의 점검 조건에 걸림 | 설정값에 근거한 판정 |
| 검증필 | 수집값 외에 정책·벤더 권고 등의 대조가 필요함 | HV-25의 버전·빌드 확인 등 |
| 오류 | 연결 또는 값 수집을 완료하지 못함 | 개별 설정의 취약 여부와 분리 |
| 해당없음 | 플랫폼·기능에 해당 항목을 적용하지 않음 | 다른 플랫폼의 결과와 구분 |

ESXi 연결 오류에서는 API 세션을 만들기 전 중단된 원인이 여러 항목에 공통으로 전달됨. 이때 항목별 오류의 개수를 실제 설정 결함의 개수로 세지 않고, 공통 수집 경로의 중단 지점부터 분석함.

## 문제 해결

### Web.py | 도움말·일반 문자열 오탐

웹 점검 실행 중 도움말·CI·일반 설정 파일의 로그인·세션 관련 단어까지 탐지되어 `점검 필요`가 과도하게 출력됨. 화면 요약에서 항목을 찾은 뒤 파일별 증적과 실제 코드 동작을 대조함.

1. **탐지 위치 확인** — JSON의 파일 경로·줄 번호·일치 코드로 경보가 발생한 위치를 찾음. 웹 인증 처리 코드 외에 도움말·CI·일반 설정 파일이 포함된 것을 확인함.
2. **문자열과 처리 동작 구분** — 로그인 페이지로 이동하는 로그아웃 코드를 확인함. 로그인 관련 문자열은 있으나 계정 입력을 받아 인증하는 처리기가 아니므로 오탐으로 분류함. 일반 설정 문자열도 같은 기준으로 대조함.
3. **제외 조건 수정** — 파일 경로 제외와 인증·세션 패턴 조건을 나눠 수정함. 도움말·문서·테스트 경로는 제외하고, 소스 파일 안에서는 실제 로그인 처리와 세션 초기화에 해당하는 패턴을 남김.
4. **수정 결과 비교** — 회귀 테스트에서 도움말·일반 문자열이 빠지는지와 실제 인증·세션 처리 코드가 계속 탐지되는지를 함께 확인함. 보호 조건의 추가 확인이 필요한 로그인 처리기는 검토 대상으로 유지함.

| 수정 대상 | 변경 내용 |
| --- | --- |
| 파일 경로 | 도움말·문서·테스트 경로 제외 |
| 인증·세션 코드 | 실제 로그인 처리와 세션 초기화 패턴으로 조건 축소 |
| 일반 문자열 | 로그인 페이지로 이동하는 로그아웃 코드와 일반 설정 문자열 제외 |
| 추가 검토 대상 | 보호 조건의 추가 확인이 필요한 로그인 처리기 유지 |

### VH.py | ESXi 연결 오류

ESXi 점검 실행 중 필수 패키지 누락, Python 3.9·pyVmomi 버전 불일치, TLS 인증서 검증 실패가 차례로 발생함. 설정 수집 전 실행이 중단되어 오류 메시지를 패키지 로딩·버전 호환·인증서 검증 단계로 나눠 분석함.

1. **패키지 로딩 확인** — 필수 패키지가 없는 상태에서는 접속 정보 입력 이후에도 설정 수집을 시작할 수 없음. 플랫폼별 필수 패키지를 먼저 검사하도록 실행 순서를 변경함.
2. **버전 호환성 조정** — Python 3.9 환경에서 pyVmomi 버전 문제를 확인하고 당시 설치 버전을 9.0.0.0으로 조정함. 재실행 결과 모듈 로딩 단계를 통과하고 TLS 검증 단계로 진행됨.
3. **인증서 오류 분리** — 이후 오류를 패키지 문제와 분리해 CA 신뢰 설정·호스트명 확인 문제로 분석함. CA 파일을 지정하는 접속 방법을 정리함.
4. **중단 지점 확인** — TLS 연결 문제는 해결되지 않아 ESXi 로그인·전체 설정 수집 미완료. 공통 연결 오류가 HV-01~HV-25에 전달되어 오류 25개 출력됨. 개별 설정 검사 이전의 연결 실패로 구분함.

| 단계 | 변경·분석 내용 | 결과 |
| --- | --- | --- |
| 패키지 확인 | 플랫폼별 필수 패키지를 접속 정보 입력 전에 검사하도록 변경 | 누락 여부 사전 확인 |
| 버전 호환성 | 당시 환경의 pyVmomi를 9.0.0.0으로 조정 | 모듈 로딩 통과 |
| 인증서 검증 | CA 신뢰·호스트명 문제 분석, CA 파일 지정 방법 정리 | TLS 검증 단계까지 진행, 연결 문제 미해결 |
